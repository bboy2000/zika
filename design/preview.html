为什么详情改回弹出式　v1.01 做成了整页详情，手机上一屏只有一个字显得空，平板上还得拆成"左书写 / 右信息"两栏，两套布局两套断点。改回弹层后：手机从底部弹出、关掉即回列表，孩子的动作是"看一眼就走"，不丢上下文；平板同一份内容居中限宽 560 即可，一套结构两端通用，不需要为平板单独排版。

◆
问题：小程序不能外挂字体，iOS 有楷体、多数 Android 没有——直接写 font-family:"KaiTi" 会变成「iPhone 楷体、安卓黑体」，同一个字两端不一样，对识字是负面的。所以要主动把字体文件带进去。三条路线：
路线做法优点代价结论
A 系统楷体 + 黑体兜底
font-family:"KaiTi","Kaiti SC",…,sans-serif		 零成本，立刻能写。原版 Web 就是这么上线的 安卓端实际是黑体，两端不一致 兜底用
B 字体子集 + wx.loadFontFace
只保留本库 2307 个字的 woff，约 600-900KB，放云存储，App 启动时加载一次全局生效		 全端统一楷体；字体渲染是原生排版，列表滚动最流畅；组词、释义、页眉都能一起用 首屏有几百毫秒字体空窗（可先显示系统字再切换）；需选一个可免费商用的楷体 推荐
C canvas 逐字绘制
用 hanzi-writer-data 的笔画路径直接画		 与笔顺动画完全同源，字形最接近课本；不用任何字体文件 列表里多个 canvas，滚动性能与首屏渲染有风险；文字不能选中、不能用于页眉 只用于田字格/笔顺
✓
我的建议：B 为主 + C 专用于田字格。列表、详情大字、组词、释义全部走 B 的楷体；田字格与笔顺动画本来就必须 canvas，走 C。这样全站是楷体，且「写」的动画和「认」的字形都是楷体结构。

字体选型：推荐 文鼎 PL 楷（AR PL UKai）——开源可商用（Arphic Public License，允许嵌入与子集化），而且 hanzi-writer 的汉字数据正是从这款楷体提取的，与笔顺动画 100% 同源，不会有「大字一个样、写起来另一个样」。备选霞鹜文楷（OFL，更秀气，但字形与笔顺数据不同源）。

这一条需要你拍板：选 AR PL UKai（与笔顺同源）还是霞鹜文楷（更好看）？定了我在 P1 一起把字体子集脚本写出来。
